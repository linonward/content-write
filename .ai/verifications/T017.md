## 决定

- 渲染器位置：放在 API 的 `article-export` 模块，而不是新建共享包。预览页通过 `GET /api/articles/:id/preview` 取得清理后的片段，HTML 导出嵌入同一片段，因此只有一条渲染链，Web 端不加载 remark/rehype，也不接触数据库与密钥。只有 API 使用渲染器；若以后 worker 也需要，再抽成包。
- 原始 HTML：丢弃（remark-rehype 不开启 `allowDangerousHtml`），不转义显示。之后 `rehype-sanitize` 仍按白名单清理（只允许标题、段落、列表、引用、代码、强调、链接、分隔线与图片占位），再检查链接必须是绝对 http(s)/mailto 并加 `rel="noopener noreferrer nofollow"`。
- 图片：不渲染 `<img>`。http(s) 图片变为文字链接 `[图片：alt]`，其他图片只留文字，作者在公众号编辑器里重新插图。这样预览与导出都不会自动拉取远程图片（9.3）。
- HTML 导出是独立文档：内联样式、`<meta charset="utf-8">`、`Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`、`no-referrer`。接口响应另加 `nosniff` 与 `sandbox` CSP。
- Markdown 导出是作者原文（`# 标题` 加正文），以附件下载，不经过渲染。
- 下载：页面用带 Cookie 的 `fetch` 取文件再保存，失败时错误留在页面上；文件名由预览接口返回的 `fileName` 生成，与服务端 `Content-Disposition` 同源同规则。
- 参考文章：导出模块只查询 `articles`（按 `user_id` 与 `id`），不读取 `reference_articles` 或框架快照。

## 偏差与说明

- 文章页入口暂名“预览”，放在“返回文章列表”旁；设计稿顶栏的“预览与发布”与阶段条属于 T031（发布页），届时替换。预览页沿用现有页头，没有实现设计稿的侧栏外壳（同 T029 的记录）。
- 预览手机框内不显示设计稿中的作者名与发布日期（没有可信的作者展示名），改在左侧显示“版本 N · 渲染时间”。
- 只支持 CommonMark：表格、删除线、任务列表会按普通文字显示。
- 预览样式在 Web 的 CSS 模块，HTML 导出样式在渲染器内联，两处需同步维护（已在两处注释互相指向）。
- `apps/api/src/modules/articles/routes.ts` 为 `/articles/*` 注册的会话中间件也会匹配新路由，已登录请求可能查两次会话；未改动文章模块以免与 T030 冲突，影响只是多一次查询。

## 风险

- 公众号编辑器会再次调整样式，预览只是近似（页面已提示）。
- 图片需作者在公众号后台重新插入；如果后续要支持图片，需要先有对象存储与代理，不能直接加载远程地址。
