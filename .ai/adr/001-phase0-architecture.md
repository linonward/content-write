# ADR 001：Phase 0 模块化单体架构

状态：采用（T001 建立单体基线，T002 明确模块边界）

采用 Next.js App Router、React、TypeScript、PostgreSQL、Drizzle 和独立 Node worker。Web API 负责鉴权与短请求，后续长任务写入 PostgreSQL，由 worker 领取。T001 worker 只验证进程与数据库连接，不预先实现队列。

## 模块边界

一个仓库、一个 Web 应用、一个常驻 worker、一个 PostgreSQL 数据库。Web 与 worker 是同一业务系统的两个进程，不拆成微服务。按业务能力组织 `src/modules/`：

| 模块 | 职责 |
|---|---|
| `identity` | 邀请账号、登录、会话、权限与当前用户 |
| `materials` | 素材、版本、提取结果与检索 |
| `ideas` | 选题及来源关系 |
| `articles` | 大纲、正文、版本、编辑建议、预览与导出 |
| `author` | 作者画像、样本与记忆 |
| `publication` | 手动发布记录 |
| `feedback` | 反馈与产品事件 |
| `ai-jobs` | 持久任务、模型调用、用量和 worker 调度 |

模块在对应垂直任务首次需要时建立，不预先创建空目录或业务表。模块内按实际复杂度放 `server/`、`client/` 与共享的类型和校验；服务实现业务规则，仓储封装持久化。`src/app/` 只负责页面、Route Handler、输入输出适配和调用模块服务。`src/worker.ts` 只负责启动与调度，任务执行进入所属模块。通用数据库连接、错误格式和配置放 `src/server/`，不能承载业务规则。

跨模块只能调用对方公开的服务或查询接口，不直接读写别的模块的表，也不导入别的模块内部仓储。数据库迁移、关系声明和事务编排可在服务端明确依赖多个模块的 schema；需要跨模块原子操作时，由用例服务协调同一数据库事务，并记录所有权边界。共享类型只包含稳定契约，不把所有业务模型集中成一个全局模块。

服务端代码不得被客户端组件导入。认证身份在每个 API 和服务端动作中校验，用户归属由服务端会话决定。数据库和模型密钥只在服务端及 worker 使用。长任务通过 PostgreSQL 持久队列衔接 Web 和 worker，不能用进程内队列或请求结束后的 Promise。模块化边界由代码评审和导入检查保持；出现实际复杂度后再考虑自动化边界规则。

理由：一个 Web 应用和一个 worker 足以支撑首轮试用，并可在后续切片中验证真实任务恢复。业务表随功能增加，避免一次性建立未使用结构。

差异：T001 暂不加入 Better Auth、CodeMirror、TanStack Query、PostHog 或 AI Adapter；它们在首次需要的垂直任务加入。T001 的首页仅展示工程状态，不代表完整 `/home`。
