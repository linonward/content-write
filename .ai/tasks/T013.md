## 用户结果

作者在正文中选中一段文字，写一句修改要求（或选用"更精简""更口语"等常用要求），主动请求 AI 修改建议。建议先作为候选显示：原文与建议的差异、修改说明和待补证据。作者选择应用后，选区被替换为新版本并写入历史；选择拒绝则正文不变。全文修改需要作者明确切换到"全文"。正文在建议生成后发生变化时，建议标为过期，不能应用，只能重新生成。

## 垂直范围

- 数据：迁移新增 `edit_suggestions`：文章、用户、任务（唯一）、基础版本、范围（`selection` / `full`）、选区开始与结束（UTF-16）、选区原文、修改要求、`replacement`、`explanation`、`evidence_gaps`、状态（`pending` / `ready` / `applied` / `rejected`）、`applied_version`、mode。请求时由服务端写入选区信息，worker 只补模型输出。`article_revisions.source` 增加 `ai_edit`。
- API：`POST /api/articles/:id/edit`（`expectedVersion`、`scope`、`start`、`end`、`selectionText`、`instruction` + `Idempotency-Key`，202）；`POST /api/articles/:id/suggestions/:sid/apply`（`expectedVersion`）；`POST /api/articles/:id/suggestions/:sid/reject`；`GET /api/articles/:id` 增加 `suggestions` 与 `latestEditJob`。
- worker：`edit_suggestion` 任务。领取后与提交前都核对文章仍为基础版本、选区原文未变；否则 `stale`，不调用模型或不保存结果。确定性 mock；DeepSeek 关闭思考。
- 页面：编辑器旁的"AI 修改"面板：显示当前选区、范围切换、修改要求、常用要求、生成状态；建议卡片显示差异、说明、待补证据、应用与拒绝；过期建议明确标出。未配置生成服务、未生成正文、正文有未保存修改时不显示为可用。

## 规则

- 选区按 JavaScript UTF-16 计算，服务端以 `body.slice(start, end)` 为准记录原文；客户端提交的 `selectionText` 必须一致，否则 409（编辑器与服务器内容不一致）。
- 选区原文去除空白后不能为空，最多 8,000 字符；全文修改要求 `start = 0`、`end = 正文长度`，正文超过 8,000 字符时提示分段修改。修改要求 1～500 字。
- 输入摘要绑定文章基础版本（文章来源版本创建后不变，由基础版本确定）、范围、选区位置与原文、修改要求与 mode；同键同输入返回同一任务，不同输入 409；幂等先于版本检查。同一文章同时只允许一个修改任务；复用每日额度、并发与截止时间；DeepSeek 模式需要确认。
- 模型只提供 `replacement`、`explanation`、`evidenceGaps`；素材是数据，不新增事实，缺证据列入 `evidenceGaps`。选区首尾空白由服务端保留。
- 应用前校验：本人文章、本人建议、建议已就绪、文章版本等于建议基础版本且等于 `expectedVersion`、选区原文仍一致；替换后正文不超过 50,000 字符。应用生成新版本并同事务写入 `ai_edit` 历史。重复应用同一建议返回当时生成的版本，不再改动。
- 拒绝只改建议状态；已应用的建议不能拒绝，重复拒绝幂等。
- mock 结果明确标注，不代表真实修改质量。

## 实施记录

- 新 API 模块 `apps/api/src/modules/article-edits`（routes → service → repository），不再扩大 `articles` 模块；复用 `articles/repository` 的 `lockArticle` 与 `updateArticle`。新增查询全部用 Drizzle。
- 选区是否仍有效（基础版本 + 原文一致）放在共享包 `packages/db/src/edit-suggestions.ts` 的 `selectionCurrent`，API 应用与 worker 领取、提交共用。
- 建议行在请求时由 API 创建（`pending`），worker 只补模型输出并改为 `ready`；任务失败或失效时行保持 `pending`，不在列表中显示。
- 加锁顺序：文章 → 建议，API 应用与 worker 提交一致。
- 页面：`MarkdownEditor` 报告 CodeMirror 主选区（UTF-16 偏移，与 API 一致）；`BodyEditor` 在 `lg` 宽度以上把 `AiEditPanel`（宽 320，`w-80`）放在编辑器右侧，窄屏排在下方。T032 合并后改用设计 token 与组件：模拟徽标 `mock` 变体、过期 `StatusPill`、证据缺口 `evidence-soft` 区块、建议之间细线分隔（面板内不嵌套面板），面板只保留“生成修改建议”一个主按钮，应用为次按钮、拒绝为幽灵按钮。差异用 `diff@8.0.4` 的 `diffChars`（200 ms 超时后改为分别显示原文与建议）。正文有未保存修改、保存失败或冲突时不能请求或应用。
- worker 的 `staleJob` 增加错误码参数（默认值保持原 `MATERIAL_VERSION_CHANGED`）。
- E2E 手机视口下 Playwright 逐键输入中文会被 CodeMirror 的 Android 输入处理丢字，测试改用 `insertText`（等同输入法一次提交）；桌面逐键输入正常。
