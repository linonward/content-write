## 用户结果

创始人得到一份可批准或否决的决策：是否提供 Claude Code Skill 入口，让作者在 Claude Code 里贴一篇文章完成拆解、选自己的素材按框架生成大纲，结果写回 Web 端账本。

## 背景

Web 产品需要作者主动来访，分发弱；首批用户里的程序员、产品经理和独立开发者已在使用 Claude Code。Skill 入口借用现有工作环境，Web 端保留素材、版本、记忆与发布记录。

## 需要回答

1. 鉴权：现有只有邀请制邮箱密码会话。个人 API token 的签发、作用域（拆解、读素材列表、创建文章与大纲）、撤销和限流；token 不写进 Skill 文件。
2. 接口面：最少需要哪些 API；是否复用现有路由，还是新增面向 token 的薄层；异步任务用轮询还是等待。
3. 模型：Skill 调用本产品 API（服务端 DeepSeek，额度与用量记在账本），而不是让 Claude 自己拆解；写明不这样做会失去什么。
4. 合规：每一步仍由作者在会话里触发和确认；Skill 不推送草稿箱、不发布；参考文章原文与 T038 的复制检查规则同样适用。
5. 分发与验证：Skill 怎么到达作者手里（插件市场、仓库、手动安装）；用哪个信号判断它比 Web 入口更能带来使用。
6. 成本：实现工作量估计与对 T031、T019 等任务的影响。
