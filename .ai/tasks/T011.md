## 用户结果

作者在文章页用 Markdown 编辑器修改标题和正文。停止输入 1 秒后自动保存，并显示保存中、已保存或失败。保存失败时正文留在本机，刷新后可以恢复；别处已有更新版本时不覆盖，提示作者载入最新版本，本机内容仍可找回。退出登录时清除本机副本。

## 垂直范围

- 数据：迁移新增 `article_revisions`（文章、用户、版本、标题、正文、来源 `edit` / `draft`、时间；文章 + 版本唯一）。迁移为已有正文的文章补写当前版本的历史。
- API：`PUT /api/articles/:id/body`，携带 `expectedVersion`、`title`、`body`；按版本条件原子更新，成功版本加一，并在同一事务写入历史。初稿直接成为正文和应用候选也在同一事务写入历史。
- 页面：CodeMirror Markdown 编辑器替换只读正文；标题输入框；保存状态；冲突提示；本机恢复提示。
- 本机副本：保存失败或冲突时，以"文章 ID + 基础版本"保存到 `localStorage`。载入时：副本基础版本等于服务端版本 → 提示恢复；服务端更新 → 说明副本基于旧版本，作者明确选择后才放进编辑器。退出登录清除全部副本。

## 规则

- 标题最多 200 字，正文最多 50,000 字符；超出 413，前端同时限制。
- 版本冲突返回 409，不覆盖正文；编辑器暂停自动保存，直到作者载入最新版本。载入后本机副本作为"基于旧版本"的内容提供，作者明确选择才放回编辑器。
- 本机副本不会自动覆盖服务端内容。
- 只有正文或标题变化才写历史；brief、大纲的修改不写正文历史。

## 实施记录

- 正文历史写入函数 `recordRevision` 放在 `@content-write/db/article-revisions`，api（编辑、应用候选）与 worker（初稿直接成为正文）共用。
- 自动保存成功后只更新页面中文章的版本、标题和正文，不重新拉取整页。否则会冲掉 brief 或大纲里尚未保存的输入。修改 brief 或大纲只会提升版本，正文不变，此时编辑器自动换到新版本，不报冲突。
- 本机副本在每次尝试保存前写入，服务端确认后删除；关闭页面时如有未保存内容也会写入并提示。
- 编辑器用 CodeMirror 6（`codemirror` 6.0.2、`@codemirror/lang-markdown` 6.5.2、`@codemirror/state` 6.7.6、`@codemirror/view` 6.43.13，版本取自 npm registry），在 effect 中挂载。Web 新增 `test` 脚本运行 Vitest 单元测试。
- 集成测试的登录、请求和数据准备函数从 `drafts.test.ts` 抽到 `tests/integration/helpers.ts`，供多个文件复用。
