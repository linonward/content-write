## 用户结果

T010 前修复已集成切片中的任务、配额与 API 结构问题，避免后续生成任务继续复制：删除素材不能重置每日生成额度或抹掉用量；素材整理面板只显示整理任务；任务查询与重试按任务类型返回正确结果；worker 失败可诊断且不可恢复的错误不重复尝试。

## 范围

- 每日逻辑生成额度改为独立计数表，按 Asia/Shanghai 自然日累计；删除素材、选题或文章不回退额度。迁移根据现有任务回填当日及历史计数。
- `ai_runs` 在任务删除后保留，`job_id` 置空；仍随用户删除。
- 选题与大纲任务不再借用 `ai_jobs.material_id`，旧数据迁移置空；`ai_jobs.article_id` 增加外键。素材状态、整理面板与任务重试只关联 `material_analysis`。
- `GET /api/jobs/:id` 返回任务类型；`POST /api/jobs/:id/retry` 只接受素材整理任务，其余类型返回 409。
- API 共享错误、JSON 读取、Idempotency-Key、会话与 Origin 中间件和 `WEB_ORIGIN` 配置；生产环境缺少 `WEB_ORIGIN` 时 API 拒绝启动。503 与并发上限响应标记为可重试。
- 入队的幂等、截止清理、额度与并发判断收敛到 `ai-jobs` 模块；任务查询与重试路由迁入该模块。
- worker 按任务类型注册处理器；失败记录任务 ID、类型、尝试次数和错误类别，不记录正文；`AI_NOT_CONFIGURED` 等不可恢复错误直接失败。

## 实施记录

- `apps/api/src/http.ts`、`config.ts`：统一错误响应（503/500 默认可重试）、JSON 读取上限、Idempotency-Key 校验、`requireUser`（会话 + 写请求 Origin）与懒读取的 `WEB_ORIGIN`；`index.ts` 在生产缺少 `WEB_ORIGIN` 时拒绝启动。materials、ideas、articles、identity 与 `app.ts` 改用这些辅助，删除各自的复制实现。
- `apps/api/src/modules/ai-jobs/`：`queue.ts` 提供用户级咨询锁、幂等查找与 `enqueueJob`（截止清理、每日额度与并发、写入额度账本、插入任务，同一事务）；三种生成入口改为调用它。任务查询与重试路由从 materials 迁入，返回 `kind`，只重试素材整理任务。
- 数据（迁移 0008）：新增 `ai_daily_usage(user_id, day, count)`，回填历史任务；`ai_runs.job_id` 改为可空并 `ON DELETE SET NULL`；`ai_jobs.material_id/material_version` 改为可空，非整理任务置空；`ai_jobs.article_id` 外键级联，指向不存在文章的旧任务标记为 stale 后置空。素材整理面板与素材列表状态只读取 `material_analysis` 任务。
- worker：`failures.ts` 区分可重试错误与 `TerminalJobError`；处理器按 `kind` 注册，领取查询只选已注册类型；失败日志只含任务 ID、类型、尝试次数、错误码和错误类别。
- 行为变化：删除素材仍删除其任务、分析、选题与文章，但模型运行记录保留（无正文、无任务关联），每日额度不回退；非整理任务调用重试返回 409 `JOB_NOT_RETRYABLE`；文章已有排队大纲任务时，返回 `OUTLINE_JOB_ACTIVE` 的判断先于额度判断。
