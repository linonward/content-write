# 产品方向评估：爆款拆解到草稿箱

日期：2026-10-02
结论：**Narrow**。值得做，但只做"爆款拆解 → 作者自己的稿子 → 草稿箱"这一条人工把关的链路；全自动发布、多号改写分发、账号代管不做。
状态：前提已与用户逐条确认；付费意愿未验证（见风险 1）。实施方案待 `/think` 产出，`docs/product.md` 尚未修改。

## 问题陈述

做垂直小号的个人作者难以持续更新。一篇文章里最耗时的是找选题，其次是写初稿；排版已有 135 编辑器等现成工具，不是痛点。作者希望参考已经被验证的爆款文章，但手工拆解慢，照着改又会变成洗稿。

## 目标用户

想靠垂直小号获得流量主收入、需要持续更新的个人作者，通常运营 1 到 3 个号；长期包括管理多个号的个人或小团队。

- 已知用户：创始人本人，每周写公众号十几个小时；找选题靠刷同行公众号和知乎热榜；目前号没有收入。
- 尚无可点名的外部用户。

## 需求证据

| 证据 | 强度 |
|---|---|
| 创始人每周十几个小时，找选题最耗时 | 真实痛点，但 n=1，且本人号无收入，不能代表付费意愿 |
| 平台扶持小号：流量主门槛降到 100 粉，推荐约 70% 来自算法，新号有 30 到 60 天扶持期 | 时机成立 |
| 推荐权重最高的是完读率与分享率 | 奖励质量而非数量，支持"人工把关" |
| 有人为此付费 | **无** |

来源：[100 粉开通流量主](https://www.xmyeditor.com/geo/10901)、[2026 推荐机制变化](https://www.xmyeditor.com/geo/10867)、[新手扶持期](https://www.jzl.com/news/222)。

## 现状与竞争

- 现状：免费，刷同行公众号与知乎热榜，自己拆解，自己写，135 排版。
- 免费开源的全自动方案已经很多（WeWrite、wechat-publisher、AIWriteX、ai-trend-publish），覆盖热点、选题、写作、排版、推送草稿箱；它们都处在平台禁止的"非真人自动化创作"范围内。
- 差异化不在"能自动化"，而在：合规（每步有人确认、最终人工发布）、以作者自己的素材为来源、拆解只取结构不搬文字、每句有出处。

## 平台约束（决定边界）

- 公众号规范禁止用 AI、脚本、接口替代真人完成创作与发布；禁止脱离真实创作者表达的生成、改写、拼接、搬运；禁止脚本或托管方式批量、连续发布；传播此类服务本身也违规。处罚包括限流、删除、能力限制和封号。来源：[第一财经](https://www.yicai.com/news/103125654.html)、[澎湃](https://www.thepaper.cn/newsDetail_forward_32950844)。
- AI 生成合成内容发布时须主动声明（2025-09-01 起）。来源：[北京日报](https://xinwen.bjd.com.cn/content/s68b3c56ce4b02424b0bf8cd5.html)。
- 图文数据统计接口只对已认证公众号开放；未认证账号没有接口权限。来源：[微信数据统计接口](https://developers.weixin.qq.com/doc/service/guide/product/analysis_data/analysis_data.html)。
- 合规的多账号接入方式是开放平台第三方平台授权（按权限集，可撤销）。来源：[第三方平台](https://developers.weixin.qq.com/doc/oplatform/developers/product/third_platform/)、[公众号权限集](https://developers.weixin.qq.com/doc/oplatform/Third-party_Platforms/2.0/product/offical_account_authority.html)。

## 最窄楔子

一次会话内完成：

1. 用户贴入一篇爆款文章链接或正文。
2. 拆解出可复用的写作框架：标题类型、开头钩子、各段功能、论证方式、情绪节奏、结尾引导。只输出结构与方法，不输出改写后的原文。
3. 用户选择自己的素材（已有素材箱）。
4. 按框架与素材生成大纲并确认（已有 T009 流程），再生成全文（已有 T010），标注来源与证据缺口。
5. 用户修改（T011 到 T013），预览并导出安全 HTML（T017）。
6. 已认证账号可推送到草稿箱；最终由作者在公众号后台手动发布。

卖点：大约 20 分钟，从一篇爆款拆解到草稿箱里有一篇自己的稿子。

复用：素材保存与链接抓取（T003、T005）、持久任务与 worker（T006、T026）、大纲与初稿（T009、T010）。新增：拆解分析类型、框架驱动的大纲生成、导出（原计划 T017）、草稿箱推送（原产品文档列为暂不实现）。

## 已确认的前提

1. 一次会话内走完"贴爆款 → 拆解 → 选自己的素材 → 生成全文 → 排版 → 推送草稿箱"，每一步由用户触发、可修改，最终由作者手动发布；不做定时、批量或无人值守的发布。
2. 拆解只输出结构与方法，不输出改写后的原文；生成内容标注 AI 生成，由作者确认后发布。
3. 不做账号代管，改为授权读取数据：已认证号走第三方平台授权（只读数据加推送草稿），未认证个人号由用户从后台导出或手动录入；产品不保存账号密码、不代发。
4. 矩阵保留为"一个人或团队管理多个号"的工作台：每个号有自己的定位、声音和数据，每篇内容以该号的素材为来源并由人确认；不做一篇改写多号分发。

## 明确不做

- 全自动、无人值守的创作与发布流水线；定时或批量发布。
- 一稿改写后分发到多个账号或多个平台。
- 保存账号密码、代替用户操作公众号后台。
- 把"爆款概率"或"照着写就能爆"作为承诺。

## 风险

1. **付费意愿未验证**（最大风险）：创始人本人的号尚无收入，没有任何外部用户表达或证明付费意愿；连续四次追问未得到回答。建议在继续扩展功能前，手动为 5 位垂直小号作者各跑一篇，询问每月价格。
2. 平台规则继续收紧：AI 辅助与"非真人创作"的边界由平台解释，需要保留每步人工确认的操作记录。
3. 目标用户多为未认证个人号：拿不到官方数据接口，草稿箱接口对未认证号是否可用需核实；数据分析需支持手动导入。
4. 与免费开源工具竞争：差异化依赖合规与"作者自己的素材"，需要在落地页和产品中讲清楚。
5. 用户贴入的爆款原文属于他人作品：只用于本人分析，不对外展示或分发，删除时一并清除。

## 对现有资产的影响

- `docs/product.md`：定位从"把自己的素材写成文章"扩展为"借爆款结构，用自己的素材写成文章"；"暂不实现"中的微信草稿箱 API 移入规划；新增拆解分析的 AI 契约与平台合规要求。
- 任务看板：T011 到 T013 方向不变；需要新增拆解与框架任务，并调整 T017、T018 与草稿箱推送的顺序。
- 设计稿与落地页：叙事改为"爆款结构 + 你的素材"；产品名待定（"公众号内容工作台"已被认为不合适）。

## 实施方案（2026-10-02 批准）

模型：DeepSeek 官方 OpenAI 格式接口 `https://api.deepseek.com`，默认 `deepseek-flash`（`AI_MODEL` 可切换为 `deepseek-v4-pro`）；JSON 输出用 `response_format: {type: "json_object"}`。2026-10-02 实测：Key 可用；思考模式默认开启，`max_tokens` 不足时思考 token 会耗尽额度并返回空正文（`finish_reason=length`）；`thinking: {type: "disabled"}` 与 `reasoning_effort: "low"` 均返回合法 JSON。部署在国内，固定出口 IP。

## 设计决策（2026-10-02 确认）

1. 模块名：导航「拆解」，路由 `/breakdowns`；列表每条称「参考文章」；主按钮「拆解一篇爆款」。"爆款"只出现在行动文案中，不进入模块名与数据结构。
2. 导航顺序：首页、拆解、素材箱、选题、文章；图标 `book-open-text`。拆解不做成素材箱的标签页，保持与自己素材分离。
3. 文章阶段条不新增"框架"阶段；从框架创建的文章在顶栏面包屑后显示"框架 · 名称 · N 段"标签，点击回到拆解、悬停显示槽位；未选框架不显示。
4. 推送草稿箱只放在发布页：已配置时为第 1 步主按钮，按钮上方说明"推送后标注为 AI 辅助生成"与"只存为草稿，请在公众号后台检查并发布"；未配置时不显示；成功显示版本与时间及后台链接，失败可重试，超时显示"结果待确认"并提供「检查结果」而非重新推送；文章有新版本时提示可再次推送。顶栏"预览"按钮改名"预览与发布"。
5. 落地页主标题「看懂一篇爆款，写出你自己的那篇。」；首屏配图为"爆款槽位结构"对"你的稿子与槽位、证据标记"；流程改为两个入口汇合；原则新增「只取结构，不搬文字」，"改动先是候选"改为"进草稿箱，由你发布"；常见问题新增"这算不算洗稿？""能直接发布吗？"。真实模型接入与试用开放前不上线。
6. PR 顺序：设计系统基线 → 产品方向与文档 → 新方向设计更新；T028 可与第三个 PR 并行，T029、T030 在第三个 PR 合并后开工。
