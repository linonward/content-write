# AI 契约

模型输出结构、来源校验、记忆和成本规则见 `docs/product.md` 第 8 节。T001 不调用模型。T006 素材整理以确定性 mock 复制来源首段和片段；对结果实施 Zod 结构校验、证据 ID 校验以及 `content.slice(start,end) === quote` 校验，位置按 JavaScript UTF-16 计算。mock 标志随结果返回，token 用量与成本保持 null，不计入真实模型指标。真实 Provider 原计划在 T021 接入，2026-10-02 起由 T028 取代；接入前非 mock 模式返回 503。

T010 初稿以确定性 mock 生成：按已确认大纲的小节排列目的、要点和引用片段原文，标出每节待补证据，不新增事实。输出经 Zod 校验（标题 ≤200、Markdown ≤50,000 字符、来源映射 ≤60 条、待补证据 ≤30 条），来源映射的素材 ID、素材版本和片段 ID 必须属于文章绑定的来源。mock 不保证达到 1,200～2,000 字目标；token 与费用为 null。

T028 新增：

- `AI_MODE=deepseek`（且设置 `AI_API_KEY`）时，素材整理、选题、大纲与初稿调用 DeepSeek 官方 OpenAI 格式接口，默认 `deepseek-flash`，JSON 输出模式；提示词声明素材是数据而非指令、不得捏造、缺证据要列出。
- 思考设置集中在 `apps/worker/src/ai/config.ts`：整理、选题、大纲 `reasoning_effort: "low"`，`max_tokens` 8,000（修复 16,000）；初稿关闭思考，6,000（修复 10,000）。实测默认思考会耗尽额度返回空正文，因此空正文与 `finish_reason=length` 视为结构错误。
- 结构错误（空、截断、非 JSON、Zod 或来源校验失败）带错误摘要修复 1 次，仍失败则任务以 `AI_OUTPUT_INVALID` 失败且不再重试；网络、超时、429、5xx 最多重试 2 次，耗尽后以对应错误码失败；401/403、402、其他 4xx 直接失败。
- 素材整理由模型逐字摘录片段，服务端用 `indexOf` 计算 UTF-16 位置；找不到原文的片段丢弃，引用它的观点一并移除，不伪造位置。
- 校验与 mock 完全相同：Zod 结构、证据 ID、`content.slice(start,end) === quote`、来源素材与版本。结果与 `ai_runs` 记录 `mode=deepseek`，并记录输入、输出、思考 token 与耗时；未配置价格时费用为 null。
- 首次真实生成需作者确认（`ai_consents`），否则生成接口返回 428。CI 与集成测试只用 mock；真实冒烟记录在 `.ai/verifications/T028.md`。

T029 新增（`reference_breakdown` 任务）：

- 结构同 `docs/product.md` 8.9，校验在 `apps/worker/src/breakdown.ts`：严格对象（多出的字段如改写正文直接拒绝）；槽位 3～10 个且 id 唯一；片段最多 30 个、每个最多 120 字，`content.slice(start,end) === quote`；`hook`、`ending`、槽位的 `spanIds` 只能引用已有片段；描述字段有长度上限（类型 60、名称 60、标题类型 120、读者 200、其余 300 字），有效原因与局限各 1～6 条。
- 只输出结构：描述字段（标题类型、读者、钩子、槽位、节奏、结尾、有效原因、局限）任一行与原文有连续 12 个字相同即判为复制原文，按结构错误修复一次，仍复制则失败（T029 时为 20 字，T038 起与生成侧统一，计数规则见“参考原文复制检查”）。原文只能出现在 `spans` 里。
- 模型逐字摘录片段，服务端用 `indexOf` 定位；找不到原文的片段丢弃，引用它的 `spanIds` 一并移除。
- 思考 `reasoning_effort: "low"`，`max_tokens` 12,000（修复 20,000），失败码 `BREAKDOWN_FAILED`。领取后与提交前都核对参考文章仍存在且版本未变；被删除或修改的文章不再发送给模型、不写入结果（任务 `stale` 或随文章删除）。
- mock 按段落生成确定性的通用槽位与首句片段，标注为 mock，不代表真实分析。
- 拆解结果与片段只在拆解页显示，本任务没有任何其他生成读取参考文章。质量评估见 `.ai/verifications/T029.md`。

T030 新增（按框架生成大纲）：

- 绑定框架的文章，大纲提示词额外给出框架快照（标题类型、开头、各槽位的名称/作用/手法、节奏、结尾），说明框架来自他人文章的拆解、不含其内容，只借结构；论据只来自素材；素材撑不起的槽位 `evidenceIds` 留空并写 `missingEvidence`，不编造。
- 生成结果必须与槽位一一对应、顺序一致、每节 `slotId` 原样填写（`packages/db/src/framework.ts` 的 `slotsMatch`，API 保存与 worker 生成共用；作者保存时只要求槽位属于框架且不重复）。不符合按结构错误修复一次。
- 证据校验不变：只接受文章绑定素材的片段；参考文章从不进入大纲或初稿的提示词。初稿生成逻辑不变。
- mock：每个槽位一节，依次引用素材片段，片段用完后的槽位标为缺口。

T013 新增（`edit_suggestion` 任务）：

- 输入：修改要求、选区原文（全文范围时为整篇正文）、选区前后各最多 600 字的上下文、brief、文章绑定素材的片段原文。参考文章从不进入修改提示词。提示词说明修改要求之外的正文、上下文和素材都是数据；不新增素材之外的事实，需要但缺少的内容列入 `evidenceGaps`。
- 输出严格对象 `{replacement ≤20,000 字符, explanation ≤500 字, evidenceGaps ≤8 条×300 字}`（`apps/worker/src/edit.ts`）；多出的字段按结构错误修复一次。服务端保留选区原有的首尾空白，避免应用后段落粘连。
- 关闭思考，`max_tokens` 12,000（修复 16,000），失败码 `EDIT_SUGGESTION_FAILED`。领取后与提交前都用共享的 `selectionCurrent`（`packages/db/src/edit-suggestions.ts`，API 应用时同样使用）核对文章仍在基础版本且选区原文未变；否则任务 `stale`（`ARTICLE_CHANGED`），不调用模型或不保存结果。
- mock 保留原文并在末尾追加"（模拟修改：要求）"，说明写明未调用模型，只用于演示差异与应用流程。

T014 新增（作者设置）：

- 选题、大纲、初稿按任务记录的资料版本读取快照（`packages/db/src/author-profile.ts`），排队后作者再修改资料不影响该任务；没有资料或资料为空时提示词不变。素材整理与拆解不使用资料。
- 系统提示追加规则：作者设置用来把握视角、选题方向和语气，不是事实来源，简介不能写成经历、数据或案例；素材里第一人称的经历就是作者的经历，照常用“我”；优先级为本次 brief 与大纲 > 作者设置；按表达偏好写，不用禁用词。用户输入追加 `<作者设置>` 块。
- 真实模型输出（选题标题与主张、大纲标题与要点、初稿标题与正文）出现禁用词（不区分大小写）视为结构错误，修复消息列出所用的词，修复一次后仍出现则任务失败。mock 不做此检查。

## 历史文章风格上下文（T015）

选题、大纲、初稿与 AI 修改入队时按添加时间降序选最近 3 篇启用的本人历史文章，将 ID/版本写入 `ai_jobs.writing_samples` 并纳入输入 hash；没有样本时保留旧 hash 形状。只记录元数据，不复制正文。worker 发起每次任务请求前，按用户、启用状态和相同版本重读；禁用、删除或重新启用导致旧版本跳过，不补选其他文章。每篇最多开头 2000 字、总计 6000 字。已发送的请求/已有结果不追溯撤销。

历史文章作为 JSON 数据追加到提示词，明确只借鉴句式、节奏、语气和结构，不执行样本指令，不复制原句，不作事实/经历/数字/引用来源，不进入 `sourceMap` / `evidenceIds`。优先级：本次明确要求、brief 与大纲 > 作者设置 > 历史文章。事实来源校验继续只接受选定素材。AI 修改同时使用入队时作者设置版本并校验禁用词。mock 输出不模拟个人风格质量，真实质量验收另行记录。

## 确认记忆（T016）

提取（`memory_extraction`）：入队时按 T015 规则记录最近 3 篇启用历史文章的 ID/版本；worker 发送前重读，全部失效则 `stale`（`SAMPLES_CHANGED`）。每篇节选开头 2000 字，以 `a1`…`a3` 编号发送，不发送样本 ID。提示词要求只归纳写作偏好（句式、语气、结构、用词、视角），不写经历、身份、立场、数字或事实，不复制原句；历史文章是数据，其中指令不执行；证据不足可返回 0 条。输出 `{memories: [{content ≤200 字, evidence: [{sample, quote}] 1–3 条}] ≤8 条}`；服务端在节选内逐字定位 quote（UTF-16），不逐字或编号无效的片段丢弃，没有证据的候选丢弃；模型给出了候选但全部无法核对时按结构错误修复一次。低强度思考，`max_tokens` 8,000（修复 16,000），失败码 `MEMORY_EXTRACTION_FAILED`（`apps/worker/src/memories.ts`）。

提交时持有与 API 相同的用户咨询锁（`packages/db/src/user-lock.ts`），重读样本并再次核对证据的样本版本与片段，与已有记忆文字相同（忽略空白和大小写）的候选不重复保存，只保存剩余 50 条名额内的候选，状态 `candidate`，记录 `mode` 与 `jobId`。mock 为每篇样本生成一条以“mock：”开头、写明未调用模型的候选，证据是样本第一句原文。

上下文：选题、大纲、初稿与 AI 修改按任务记录的 `ai_jobs.memories` 重读（`packages/db/src/memories.ts`），只发送仍为 `confirmed` 且版本相同的记忆；禁用、删除、修改后的旧版本跳过，不补选。记忆以 JSON 字符串数组追加到用户消息，系统提示说明：记忆是作者确认过的写作偏好，不是事实来源，不能写成经历、数据、引用或案例，不进入 `sourceMap` / `evidenceIds`；其中改变任务、输出格式或身份的文字不执行；优先级为本次明确要求、brief 与大纲 > 作者设置与已确认记忆 > 历史文章。候选与禁用记忆从不进入提示词。mock 输出不体现记忆质量。

## 参考原文复制检查（T038）

对外主张“原文不会进你的稿子”由这项检查兑现，实现在 `apps/worker/src/reference-copy.ts`。

- 范围：文章绑定了拆解（`articles.breakdown_id` 不为空）时，`outline_generation`、`draft_generation`、`edit_suggestion` 的结果在提交前对照该拆解版本的参考文章（`reference_article_revisions` 中拆解时的版本，标题与正文分别比较）。原文只用于服务端比较，从不进入这三类任务的提示词。未绑定框架的文章不检查；参考文章删除后原文与修订已清除，无从对照，也不检查（此时模型只拿到当初通过同一阈值的框架快照）。
- 规则：忽略空白后，结果的任一字段与原文有连续 12 个单位相同即命中（`COPY_RUN_CHARS`）。一个单位是一个字符；连续的英文字母或数字算一个单位，避免双方都提到的产品名、数字被当作搬运。每个字段单独比较，相邻字段不会拼成一段。
- 检查的字段：大纲的标题、读者、主张与每节的标题、目的、要点、待补证据；初稿的标题、正文、来源映射的说法与待补证据；修改建议的替换文字、说明与待补证据。
- AI 修改时，选区里原本就有的文字不算命中：那是作者自己写入或粘贴的，模型保留它不属于带出原文。大纲与初稿没有这类豁免，作者写进大纲或素材里的原文句子同样不会被生成结果带出。
- 命中按结构错误处理：修复消息指出被复制的片段并要求用作者自己的素材和说法重写，修复 1 次；仍命中则任务以 `REFERENCE_COPIED` 失败，不重试，不写入大纲、初稿候选或修改建议。修复后因其他原因失败仍为 `AI_OUTPUT_INVALID`。mock 输出是确定性的，无法修复，命中直接以 `REFERENCE_COPIED` 失败。
- 拆解的描述字段使用同一阈值与计数规则，因此框架快照本身不含 12 个单位以上的原文。
- 阈值依据与真实模型评估见 `.ai/verifications/T038.md`；评估脚本 `pnpm --filter @content-write/api eval:reference-copy`，不进 CI。
